# 项目与目录授权

默认任务运行在 `project_dir`。如需管理其他目录，可在自己的私有配置中设置额外写入根目录：

```json
"writable_roots": ["/srv/projects", "/srv/services"]
```

这只是完整配置中的一个字段，不能替换整个配置文件。上述路径仅为示例，应选择自己拥有且明确授权的目录。

## 生效规则

- 仅支持 `sandbox: workspace-write`，不能与只读沙箱混用。
- 根目录必须是绝对路径且已存在；配置加载时解析符号链接并去重。
- 新建、恢复和复制会话的 App Server 沙箱配置会携带这些根目录。正在运行的任务不会热更新授权。
- 默认项目、会话归属、审批和网络策略分别控制；额外目录不赋予其他用户访问你的会话或成果的权限。
- 文件发送仍执行项目范围、符号链接和私有路径检查，不因额外写入根目录而开放任意文件导出。

## 修改配置

由部署者在服务器编辑私有配置，保留原凭证、项目和状态位置。不要提交配置正文、认证材料或会话数据。通过候选程序 `--check` 检查配置，再按 [维护流程](../LAUNCH.md) 安排正常重启。

旧程序可能拒绝不支持的字段。升级旧安装时，先用原配置安装支持该字段的版本并核验就绪，再添加新字段并重启；同时确保回退版本能识别新配置。

## 验证

配置单元测试覆盖目录存在性、路径归一、去重、畸形字段与只读冲突；应用和协议测试覆盖不同会话入口、目录边界及符号链接逃逸。自动化结果不代表某个实际部署已获得目录权限；实际操作需要在自己的授权环境中另外核验。
